Why the pinned column exists. CI on main went red at commit 9a3d2a5 with two
failures, and neither was a defect in the engine:

  g++ Release           FAIL  expression: owner_wins > 0    actual: 0 <= 0
  clang++ asan-ubsan    FAIL  expression: thief_wins > 0    actual: 0 <= 0

Failing in OPPOSITE directions, while the correctness assertion - exactly one
taker per round - passed 2000 of 2000 in both. A real ordering bug cannot
produce "always exactly one winner, but always the same one". The guard was
asserting a scheduling outcome.

Reproduced locally by pinning to one core: the old test fails with the identical
message, the new one passes. That reproduction is what distinguished "over-strict
test" from "real race" - without it, the honest options would have been to guess
or to leave main red.

The pinned run then found a SECOND instance (the steal counter) and, after that
was replaced, a THIRD in the replacement itself (steal_attempts). All three are
now gone, and CI runs the suite pinned to one core so a fourth cannot land
quietly.
