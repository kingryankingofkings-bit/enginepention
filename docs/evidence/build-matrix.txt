15 tests registered in the six non-sanitizer configurations: 14 C++ binaries
plus the Rust boundary suite (9 tests). 14 in the four sanitizer

Why Rust is skipped under sanitizers, stated rather than glossed: a sanitizer
build instruments the C++ archives, and linking those into a Rust binary that
was not instrumented the same way produces link errors or a binary whose runtime
checks disagree with each other. Stable Rust has no matching sanitizer support.
The C++ side - which owns all the threading - keeps full sanitizer coverage.
What is NOT covered is the FFI boundary itself under a sanitizer. That is a real
gap, and it is recorded here rather than left implicit.

The hybrid boundary (ADR-0009) is exercised by tests on both sides:
  - engine/jobs/tests/c_api_test.cpp    - 7 tests, C ABI from C++
  - rust/crates/pn-jobs/tests/boundary.rs - 9 tests, Rust closures on C++ workers

Both assert the crossing frequency directly: a 50,000-element loop at grain 512
crosses the boundary 98 times, not 50,000. If a change ever makes the boundary
fine-grained, those tests fail loudly instead of quietly costing an order of
magnitude.

Also verified: a panicking Rust chunk body is contained at the trampoline and
reported as an error rather than unwinding into C++ frames, which would be
undefined behaviour; remaining chunks still run; and the scheduler stays usable
afterwards.
